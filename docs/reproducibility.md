# Reproduction and deployment notes

## Toolchain

Install a recent Foundry release, Circom 2.1.6 or compatible, Node.js, and the exact `circomlib`, `circomlibjs`, and `snarkjs` versions recorded in your experiment manifest. Pin resolved versions and hashes before publishing numerical results. The prototype intentionally does not ship a trusted setup, generated verifier, or deployed Poseidon bytecode.

```sh
forge test -vv
python3 -m unittest discover -s model -p 'test_*.py'
circom circuits/KnowledgeOfSecret.circom --r1cs --wasm -l node_modules -o build
snarkjs r1cs info build/KnowledgeOfSecret.r1cs
```

Install `circomlib` into `node_modules` for the circuit include. Run a fresh Groth16 ceremony with a power-of-tau file of sufficient size, contribute independent entropy, and retain transcript hashes. Example commands after the initial setup (see the official Circom guide for the entire setup):

```sh
snarkjs groth16 setup build/KnowledgeOfSecret.r1cs ceremony.ptau build/initial.zkey
snarkjs zkey contribute build/initial.zkey build/final.zkey --name="independent contribution"
snarkjs zkey verify build/KnowledgeOfSecret.r1cs ceremony.ptau build/final.zkey
snarkjs zkey export verificationkey build/final.zkey build/verification_key.json
snarkjs zkey export solidityverifier build/final.zkey build/Verifier.sol
```

The circuit public signal order is `[commitment, roundId, participant]`. Sample `secret` uniformly below the BN254 scalar modulus. Compute `commitment = Poseidon([secret, roundId, BigInt(address)])` using the matching circomlibjs release. Pass input JSON with all four values as decimal strings to the generated witness calculator. Generate and locally verify a proof:

```sh
node build/KnowledgeOfSecret_js/generate_witness.js build/KnowledgeOfSecret_js/KnowledgeOfSecret.wasm input.json build/witness.wtns
snarkjs groth16 prove build/final.zkey build/witness.wtns build/proof.json build/public.json
snarkjs groth16 verify build/verification_key.json build/public.json build/proof.json
```

Deploy the generated `Verifier.sol` only after checking its ABI against `IKnowledgeVerifier`. Deploy the circomlibjs Poseidon **three-input** generated bytecode and check its ABI against `IPoseidon3`; supply both deployed addresses to the beacon constructor. Contract creation rejects empty-code addresses. The Foundry mocks are deliberately unsuitable for deployment. Convert the proof to Solidity parameters according to the generated verifier's `verifyProof` signature; in particular check the two G2 coordinates' ordering. Reject a deployment until a proof generated off-chain passes `register` and a matching reveal passes `reveal` on the intended test chain.

Use a future `commitEnd` in EVM block numbers, and a `revealBlocks` duration of at most 4096. The lock call must arrive within 256 blocks after `commitEnd`. Automated keepers improve liveness but do not change the security model.

Never commit private witness inputs, secret values intended for unrevealed rounds, setup entropy, API keys, or deployment keys. Experimental data and generated artifacts should be labeled by setup hash and source revision.
